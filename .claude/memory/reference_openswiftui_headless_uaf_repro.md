The intermittent (10s–30min) eleev/swiftui-2048 AttributeGraph UAF is now reproduced **deterministically
and headlessly** — real app, real transaction model, real input shim, NO host, NO wasi:canvas, NO graphics.
Crashes every run within ~1–4 "rounds" (seconds). This is the binary repro to judge any fix against.

## How (the "road" test the user pushed for)
Driver: `repros/swift-canvas-spike/Sources/T2iles/WandrHeadless.swift`, gated `#if WANDR_HEADLESS`
(temporary; remove once fixed). It renders the REAL `CompositeView` (via the app's own `WandrHostApp`)
through OpenSwiftUI's `renderWandrAppOnce`/`wandrRenderFrame` with a canvas-free `HeadlessSink` (records
text/rect frames), and drives the reported interaction ENTIRELY through the real input shim
`wandrSendPointer` (NOT a state hack): per round — swipes to grow the board, **RESET (header new-game
button ~(420,88) → tap "Ok")**, then navigate **Settings → About → game** via hamburger(40,88)-open +
menu-row taps. KEY: pure navigation is CLEAN (survived 400+ rounds); the crash needs the **reset** first,
exactly as the user reported ("reset the game → tap Settings → crash").

Build+run: `bash repros/swift-canvas-spike/build-headless.sh` (adds `-DWANDR_HEADLESS`,
`-ffunction-sections -fdata-sections --gc-sections`), then invoke the retained on-frame export under
wasmtime WITH 25 canvas import stubs (generated by `/tmp/.../gen_stub.py` → stub_0/1/2.wasm):
`wasmtime run -W max-wasm-stack=8388608 --preload "wasi:canvas/draw@0.0.2=stub_0.wasm"
--preload "wasi:canvas/layout@0.0.2=stub_1.wasm" --preload "wasi:canvas/types@0.0.2=stub_2.wasm"
--invoke 'wasi:input-handlers/frame-handler@0.0.2#on-frame' .build/.../T2iles.wasm 0`. Stubs never
called (CGSink gated out); the `T2iles` product is a REACTOR (`-mexec-model=reactor`) so the driver is
launched from the retained `on-frame` export (`hlOnFrame` → `wandrHeadlessRun`), not `_start`.

## The crash (3/3 runs, exit 134, wild addr 0x22e_xxxx / 0x15e_xxxx family, region ~51MB)
```
0: IAG::attribute_view::begin()            ← faults, wild read 0x22e57b10 (runs 1&2 identical)
1: IAG::Subgraph::update(unsigned char)
4: GraphHost.finishTransactionUpdate
6: GraphHost.flushTransactions             ← transaction-flush teardown
13: withoutSubgraphInvalidation            ← the DEFERRED-invalidation window (mechanism confirmed)
14: WandrRendererHost.renderFrame
```
Run 3 surfaced instead at `IAG::data::zone::alloc_bytes_recycle` (the free-list handing out poisoned
memory) — a DIFFERENT surface of the SAME corruption, and a strong tie to the "freed-then-reused graph
storage" mechanism. This is "site 2" (Subgraph::update/attribute_view) from the 3-agent map, and frame 13
`withoutSubgraphInvalidation` confirms the deferred+reentrant-teardown root, NOT plain reuse (oagreuse
showed clean teardown is benign). See [[reference_openswiftui_immortal_fix]].

  (hamburger is at y≈88, not 40).

## Real-host confirmation (2026-07-15, Windows GUI, ~10min play, render_frame #4450)
Same bug on the REAL host: `Assertion failed: _value > KindMask (AttributeID.h:93)` — that assert is in
`AttributeID::page()`; it fires when a **near-ZERO** AttributeID (`_value <= KindMask`=3, i.e. a nil/zeroed
id) is dereferenced. Same corrupted/dangling AttributeID as the headless repro, just landing LOW (zeroed)
instead of HIGH (`0x22e...` wild) — both are the same corruption. FREEZE MODE explained: the assert
ABORTS the guest → the wasmtime component instance is poisoned → every later frame traps
`cannot enter component instance` (#4451, #4452, …) → host keeps retrying → app frozen (not a clean exit).
Confirms the deterministic headless repro IS the real-host crash.

## MECHANISM ISOLATED (2026-07-15, A/B against this repro, same build, env-toggled)
`Compute/Sources/ComputeCxx/Data/Zone.cpp` — env `WANDR_IMMORTAL_GRAPH` (default ON) gates
`g_iag_disable_recycle()`:
- `=0` (reuse ON):  CRASH round 0, exit 134, wild `0x22e57b90`.
- `=1` (immortal):  NO crash, survives (round 15+ and running).
=> The UAF is **reuse of freed subgraph PAGE storage**. `zone::clear()` returns a torn-down subgraph's
pages to `table::shared()`; the next subgraph reuses them; a dangling `AttributeID` (offset into the
shared region) then resolves into a FOREIGN subgraph → wild read. Byte-level free-list reuse is NOT it
(byte-only stop-reuse still crashed); the PAGE-level leak in `zone::clear` is the delta that fixed it.
The immortal-graph change: (1) `alloc_bytes_recycle` returns fresh; (2) `realloc_bytes` doesn't write a
free-node; (3) `zone::clear` drops `_first_page` without `dealloc_page_locked` (leaks pages, mapped).

WORKING FIX = immortal graph storage (leak). Cost: monotonic memory leak (freed subgraph pages accumulate).
This is a diagnostic + stopgap, NOT the ship fix. The leak-free fix is teardown HYGIENE: before a subgraph's
pages are freed, the dangling `AttributeID`s pointing into it (StoredLocation observers, output_edges,
ancestor links, DynamicContainer refs) must be deregistered — OR a per-page/node generation stamp so a
reused offset reads as dead. See [[reference_openswiftui_immortal_fix]].

## REAL DEFECT located (2026-07-15, via WASMTIME_BACKTRACE_DETAILS=1 + DWARF file:line backtrace)
Debug tooling on wasm: `WASMTIME_BACKTRACE_DETAILS=1` + the guest's DWARF gives FULL file:line
backtraces; `-D coredump=f` dumps a post-mortem image; live LLDB via `wasmtime -g PORT` gdbstub works but
the 130MB debug module JIT-compiles too slowly (>2min) to iterate. The detailed backtrace caught the
precise surface: `_swift_release_dealloc <- CFRelease <- IAGSubgraphReleaseRef(IAGSubgraph.cpp:85) <-
DynamicViewList value-witness destroy <- AttributeType::destroy <- Node::destroy(Node.cpp:102) <-
Subgraph::invalidate_now(Subgraph.cpp:276) <- Graph::invalidate_subgraphs <- Subgraph::update <-
GraphHost.finishTransactionUpdate <- GestureGraph.sendEvents`.

ROOT = **reentrant subgraph invalidation via the CF finalizer.** Subgraph storage is a CF-refcounted
foreign-ref type; the finalizer (IAGSubgraph.cpp:40-49) does `subgraph->clear_object();
subgraph->invalidate_and_delete_(false);`. Inside `invalidate_now(B)`'s node-destroy loop, destroying a
`DynamicViewList` node releases its held `IAGSubgraphRef(C)` -> refcount 0 -> finalizer -> C's
`invalidate_and_delete_` RE-ENTERS invalidation while the outer `invalidate_now` is still iterating
B's pages/nodes -> frees/mutates storage the outer loop still holds -> wild reads / release-after-free /
`_value>KindMask`. Immortal-ON hides it (reentrant-freed pages never reused). Trigger = DynamicViewList
teardown (reset->navigate churns these containers) = the user's report.

FIX DIRECTION (leak-free, real): a finalizer firing DURING an in-progress `invalidate_now` must DEFER its
`invalidate_and_delete_` (route to the deferred path / a reentrancy guard), not recurse. Confirm the
reentrancy first (log invalidate_and_delete_ entered while invalidate_now is on the stack), then fix the
ordering in Compute. NOT ARC-bridging re-try (ruled out) — this is an ordering/reentrancy defect.
Per [[feedback_compute_goal_and_working_rules]]: this is a real Compute defect, found by read+measure, not masked.

## PROVENANCE MEASURE (2026-07-15) — page-owner map, caught at source
Zone.cpp tracks page->owner (set in alloc_slow=zone_id, cleared in zone::clear). Check in Subgraph::update's
page loop: if a page's current owner != the iterating subgraph_id -> log. Fired right before the crash:
`subgraph_id=300 (in-registry=1) page owner=2934 (REUSED-by-another)`; `id=1017 owner=1089`; and an earlier
`owner=~0` WILD page off=0x20000068. => `Subgraph::update` iterates a subgraph whose page-chain contains a
page that was FREED and REALLOCATED to a DIFFERENT subgraph (or wild). attribute_view::begin reads that
foreign page -> the 0x22e_xxxx fault. Trigger: `Subgraph::update` calls `invalidate_subgraphs()` INSIDE its
loop (Subgraph.cpp:759), freeing subgraphs/pages while the loop still holds references. `contains_subgraph`
is a POINTER search so a reused Subgraph-object pointer passes it -> still ambiguous whether the iterated
`subgraph` is (a) a stale Subgraph* reused by a new registered subgraph, or (b) live with a page freed from
its chain. NEXT disambiguator: generation-stamp Subgraph heap alloc/delete. Reentrant-finalize hypothesis
DISPROVEN earlier (638 finalizes during invalidate_now, ALL release-only subgraph=0). Instruments live in
Zone.cpp/Subgraph.cpp/IAGSubgraph.cpp (all #if wasm, remove after fix). Immortal flag default-OFF (diagnostic).

## VERDICT (2026-07-15): case (b) — LIVE subgraph loses a page from its chain
Disambiguator (live-subgraph-by-id map): the iterated subgraph is the REAL live object every time
(live-obj-for-id == ptr: id296->0x302d960, id1020->0x3110c90, id1376->0x3039fc0). NOT a stale pointer.
So a genuinely LIVE subgraph has a page in its _first_page chain that was FREED and REALLOCATED to another
subgraph (owner 532/1225) or corrupted to wild (0x20000068). Pages should only free on subgraph destruction
(zone::clear) — so either a page is cross-linked into two chains (one's teardown frees it) or a live chain's
next-ptr is overwritten by a reused page. FINAL measure to pinpoint: record page FREE HISTORY
(page_offset -> freeing_subgraph_id, seq) in zone::clear; at the mismatch report "page P of live subgraph X
was freed by subgraph Z" -> premature-self-free vs cross-linked-page. Then fix the page-ownership defect.

## RESOLVED (2026-07-15) — TWO real Compute defects found + fixed, repro flipped crash→pass, 6/6 verified
Two genuine, independent defects (found by read-first + measurement, per [[feedback_compute_goal_and_working_rules]]
— NOT guards/masks/leaks). Full derivation, code, and reasoning in
`swift/OpenSwiftUIProject/tests/oag-baseline/CROSS-LINKED-PAGE-CHAIN-FINDINGS.md`.

1. **`Graph::remove_subgraph` (Graph.cpp) was missing an erase.** `_invalidating_subgraphs` (a graph-level
   deferred-invalidation queue, pushed in `invalidate_deferred`, popped+invoked in `invalidate_subgraphs()`)
   was never pruned when a subgraph was torn down via a DIFFERENT path first (as a same-context child inside
   another subgraph's `invalidate_now`). A stale `Subgraph*` surviving in that queue, once popped after the
   object's memory was reused by an unrelated LIVE subgraph, caused `invalidate_now` to tear that innocent
   subgraph down by mistake. Classic erase-remove-idiom omission — `remove_subgraph` already did this same
   cleanup for `_subgraphs`/`_tree_data_elements_by_subgraph`/`_subgraphs_with_cached_nodes`, just not this one.
2. **`table::alloc_page` (Table.cpp) multi-page scan control-flow bug.** On a mid-scan conflict (an
   already-in-use page found while scanning for `needed_pages > 1` consecutive free pages), the code
   disqualified the candidate bit but then fell through to an UNCONDITIONAL `found = true` right after the
   loop — handing out the conflicting (already-in-use) page anyway, silently, with no free ever recorded.
   That page ends up linked into TWO zones' `_first_page` chains at once.

Fix 1 alone did not flip the repro (regression guard never fired; crash pattern shifted to
`freed-by-id=(none)` wild/untracked pages — the tell that pointed at the allocator). Fix 2 was needed too.
With BOTH applied: **6/6 clean runs, 60/60 rounds each, exit 0, zero faults** (incl. on the fully cleaned
tree with all diagnostic-only instrumentation removed) — vs 100% crash-at-round-0 before. Kept permanently:
the two fixes + one cheap `contains_subgraph()` regression guard in `invalidate_subgraphs()`'s pop loop
(`#if wasm`) that hard-fails if this bug class regresses. All heavy diagnostic instrumentation (page-owner
map, free-history map, live-subgraph registry, the `WANDR_IMMORTAL_GRAPH` bisection flag) removed — served
its purpose, not needed going forward. The `#if WANDR_HEADLESS` repro itself stays as permanent regression
infra. See [[reference_openswiftui_immortal_fix]] for the superseded per-site-guard history.
