`wit-bindgen --help` on `cargo install wit-bindgen-cli --version 0.53.1` lists only: rust, c, cpp, go, csharp, moonbit, markdown, test. **No `kotlin` subcommand.**

`skiko/skiko/src/wasmWasiMain/kotlin/generated/InternalSkikoUi.kt` and `ComponentSupport.kt` say "Generated by wit-bindgen 0.53.1. DO NOT EDIT!" at the top. This is misleading — those bindings come from a **private JetBrains fork** of wit-bindgen, not the upstream cargo-installable version. Confirmed by `find / -name 'wit-bindgen*kotlin*' -type f` returning empty.

**Why:** task 36 step 6 wanted to auto-generate Kotlin bindings for `wandr:markdown/renderer@0.1.0` for the smoke consumer. Hit this dead end after installing wit-bindgen-cli (4-min compile, wasted time). Ended up hand-writing bindings using skiko's structure as a model.

**How to apply:**

- For new Kotlin/Wasm WIT bindings, hand-write following skiko's pattern: `@WasmImport(interface, name)` external decls + canonical-ABI marshaling helpers (writeBytes, return-area allocation, etc.).
- Kotlin stdlib's `componentModelRealloc` covers the `cabi_realloc` export: `@WasmExport fun cabi_realloc(ptr: Int, oldSize: Int, align: Int, newSize: Int) = componentModelRealloc(ptr, oldSize, newSize)`. Requires `@OptIn(ComponentModelInternalApi::class)`.
- For complex return types the import-side canonical ABI differs from the export side — see [[canonical-abi-import-export-asymmetry]].
- The JetBrains fork IS public: **`github.com/Kotlin/wit-bindgen` branch `kotlin`** (`wit-bindgen kotlin …`), used by `Kotlin/sample-wasi-http-kotlin`. **BUT it is NOT a clean drop-in for us** (verified 2026-05-30): the generated bindings do NOT emit the leading `freeAllComponentModelReallocAllocatedMemory()` we require at the top of every import/export (see [[wasi-realloc-allocator-pollution]]) — skiko's `SkikoUi.kt` has that call **362 times**, all added by us. So using the generator = generate-then-patch-362-injections, not free; for our heavily-customized bindings hand-writing stays competitive. The generator is worth it mainly for a fresh, vanilla interface where you can sed-inject the freeAll. See [[reference-kotlin-wasm-component-model-status]].

Working hand-written example: `wandr-app-md-smoke/src/wasmWasiMain/kotlin/generated/MarkdownImports.kt` — covers just the `render` call (string in, document return-area, read blocks.len). Generalizing to full document tree traversal is significantly more work.
